# Peleng Hackathon 2026

Мультикамерный 3D-трек одного грузовика. На каждом кадре RF-DETR Nano ищет класс `truck`, по калибровке камер точка переводится в мировую систему координат выданных таблиц (сантиметры), а фильтр постоянной скорости сглаживает траекторию.

Команды запускаются из корня репозитория.

## Сборка и окружение

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```bash
uv sync
uv run python -m mv3d check
uv run pytest
```

`uv sync` ставит зависимости из `pyproject.toml` и `uv.lock`: OpenCV, NumPy, PyTorch, RF-DETR 1.11.2 (`rfdetr[train,augment]`), Supervision, ByteTrack (`trackers`), PyQt6, PyYAML. `check` печатает версии torch, torchvision и OpenCV. `pytest` гоняет геометрию, детектор, аугментации, CLI и окно без реального прогона по видео.

Первый прогон сам скачивает предобученные веса COCO nano в кэш Roboflow (`~/.roboflow/models/rf-detr-nano.pth`). Если уже лежит `weights/rfdetr-nano-truck.pth`, берётся он.

## Запуск

| Команда | Что делает |
|---|---|
| `uv run python -m mv3d csv` | Только таблицы. Быстрее: кадры не копируются, ролики не кодируются |
| `uv run python -m mv3d video` | Только размеченные `camN.mp4` |
| `uv run python -m mv3d track` | CSV, графики и размеченные ролики |
| `uv run python -m mv3d ui` | Окно: камеры, прогон, графики, координаты, сцена |
| `uv run python -m mv3d score outputs/track_<время>` | MSE и RMSE по уже готовому `track.csv`, без детектора |
| `uv run python -m mv3d train` | Псевдоразметка и дообучение nano, пять фолдов |
| `uv run python -m mv3d detect <файл>` | Один ролик или кадр, печать 3D-точки |
| `uv run python -m mv3d check` | Проверка, что torch и OpenCV импортируются |

Общие флаги `csv`, `video` и `track`:

```bash
uv run python -m mv3d csv --config configs/cameras.yml --frames 0 --score 0.15 --out outputs
uv run python -m mv3d csv --camera cam1
uv run python -m mv3d score outputs/track_20261104_120000_000000 --gt configs/calibration/object_transform_SM_AA_track.csv
```

- `--frames 0` — все кадры, иначе обрезка с начала.
- `--score` — порог уверенности детектора в основном проходе (по умолчанию `0.15`). Внутри пайплайна кандидаты ещё раз ищутся с порогом `0.05`, а в трекер уходит уже отфильтрованный бокс.
- `--camera cam1` — только эта камера. Точка тогда монокулярная: луч через пиксель пересекается с плоскостью `Z = object_plane_z_cm`.
- `--out` — корень, внутри создаётся папка `track_ГГГГММДД_ЧЧММСС_микросекунды`.

`detect` смотрит одну камеру из встроенного списка `cam1`…`cam5`:

```bash
uv run python -m mv3d detect configs/cam1.mp4 --camera cam1 --frame 0 --max-frames 5 --score 0.15 --plane-z 300 --out outputs/detect.jpg
```

## Как считается точка

На каждом кадре, синхронно по всем роликам:

1. **Детектор.** Один батч RF-DETR Nano на все камеры. Оставляется класс `truck`. Бокс шире 25% площади кадра отбрасывается, пересекающиеся боксы (IoU ≥ 0.5) схлопываются в более уверенный.
2. **Удержание бокса.** `BoxKeeper` держит один бокс на камеру: два подряд попадания открывают трек, внутри кадра пропажа живёт 8 кадров, у края — 90. Узкая полоска у границы не сжимает уже найденный бокс.
3. **ID.** ByteTrack (`lost_track_buffer=60` кадров, активация с уверенности 0.25). Слабая детекция продолжает трек и не открывает новый ID.
4. **Пиксель измерения.** Пока скорость неизвестна — центр бокса. Когда грузовик уже едет (горизонтальная скорость ≥ 30 см/с), берётся середина передней грани: в этой сцене начало координат актора сидит на носу.
5. **Вес вида.** `score × резкость × видимость`. Резкость — дисперсия Лапласиана кропа, половинный вес около 80. Видимость падает, если бокс ближе 12 пикселей к краю. Обрезанный или смазанный вид почти не тянет 3D-точку.
6. **Слияние.** Сначала выбирается камера, чей пиксель ближе всего к прогнозу фильтра (порог 160 пикселей; камера «запирается», пока её ошибка репроекции в допуске). Согласованные соседи добавляются, если ошибка ≤ 40 пикселей. База — пересечение луча с плоскостью `Z = 300` см. Если камер две и больше, взвешенный DLT заменяет эту точку только когда триангуляция сошлась с лучом ближе 5000 см по XY. Чужой вид не уводит точку на сотни метров. На старте, пока прогноза нет, монокулярные точки кластеризуются в радиусе 8000 см.
7. **Фильтр.** Состояние — положение и скорость, сантиметры. Шум измерения 80 см, шум ускорения 80 см/с²; дисперсия измерения делится на вес кадра. Инновация вдоль уже пройденного пути принимается целиком, поперёк — на четверть. Без детекции скорость затухает: за 5 секунд остаётся половина. Горизонтальная скорость ограничена 30 м/с, вертикальная — ±1.5 м/с.

Поза камеры читается на каждый кадр из её CSV: `Loc_X;Loc_Y;Loc_Z;Rot_Roll;Rot_Pitch;Rot_Yaw` в системе Unreal (X вперёд, Y вправо, Z вверх). В OpenCV это X вправо, Y вниз, Z вперёд. Фокус и размер сенсора (23.76 × 13.365 мм) дают матрицу `K` для 1280×720. Главная точка — центр кадра. Фокус берётся из `configs/cameras.yml` (35 / 60 / 35 / 50 / 20 мм).

## Модель

Детектор — [RF-DETR Nano](https://github.com/roboflow/rf-detr) 1.11.2, один класс `truck` (в COCO это id 8).

Порядок весов:

1. Явный путь, если его передали в `VehicleDetector`.
2. `weights/rfdetr-nano-truck.pth`, если файл есть. Его пишет `train`.
3. Иначе предобученный COCO nano. Для псевдоразметки `train` всегда берёт именно его (`pretrained=True`), чтобы фолды не учили сами себя на уже дообученных весах.

`train` устроен так:

1. Из каждого ролика конфига берётся каждый 12-й кадр (`--stride`). Кадр попадает в датасет, только если предобученный nano нашёл `truck` с порогом `--score` (по умолчанию 0.25).
2. Leave-one-camera-out: в каждом фолде одна камера целиком уходит в valid, остальные четыре — в train. Нужны хотя бы две камеры с найденным грузовиком.
3. Train размножается: поворот, отражения, кроп, яркость, чёрно-белое, негатив, сепия, перестановка каналов. Valid остаётся исходными кадрами. Те же цветовые и геометрические преобразования повторяются на лету через `TRUCK_TRAIN_AUG` (Albumentations).
4. Обучение: `RFDETRNano`, lr `1e-4`, lr энкодера `1.5e-5`, weight decay `1e-4`, EMA, early stopping с терпением 3 эпохи и порогом `0.001` по метрике. Устройство: CUDA, иначе MPS, иначе CPU. По умолчанию 8 эпох, batch 4.
5. У фолда читается лучший COCO **mAP 50:95** из `metrics.csv` (ключ `mAP_50_95`). В трекинг копируется чекпоинт фолда с наибольшим mAP: `weights/rfdetr-nano-truck.pth`. Сводка фолдов — `outputs/rfdetr_nano/cv.json`.

```bash
uv run python -m mv3d train \
  --stride 12 --score 0.25 --epochs 8 --batch-size 4 \
  --dataset data/truck --output outputs/rfdetr_nano \
  --weights weights/rfdetr-nano-truck.pth
```

Тот же сценарий на GPU есть в `notebooks/train_colab.ipynb`: клон репозитория, установка `rfdetr[train,augment]==1.11.2` и запуск обучения. Готовый `.pth` кладётся в `weights/` и подхватывается следующими `csv` / `track` / `ui`.

mAP здесь — качество бокса на отложенной камере, не ошибка 3D-координаты. Ошибку положения считают MSE и RMSE ниже.

## Метрики: MSE, RMSE, ошибка по кадру

Эталон по умолчанию — `configs/calibration/object_transform_SM_AA_track.csv`, колонки `Frame;Loc_X;Loc_Y;Loc_Z`. Кадр без эталона в среднее не входит.

На кадре, где есть и оценка, и эталон:

```
Err_X, Err_Y, Err_Z = оценка − эталон        (см)
Dist_cm = sqrt(Err_X² + Err_Y² + Err_Z²)     (см)
MSE = среднее по кадрам (Err_X² + Err_Y² + Err_Z²)   (см²)
RMSE = sqrt(MSE)                                     (см)
```

RMSE — типичное расстояние от оценки до эталона в сантиметрах. MSE в см² удобно сравнивать между прогонами, но в логе рядом всегда печатается RMSE.

После `csv` и `track` в лог идут две строки, если эталон найден:

- **по кадрам с целым эталоном** — все кадры, где фильтр выдал точку, включая кадры без детекции, где точка только предсказана;
- **на кадрах с детекцией** — только кадры, где слияние дало измерение.

`score` детектор не запускает. Он читает готовый `track.csv` (или папку прогона), пишет `errors.csv` и печатает одну пару MSE/RMSE по кадрам, где заполнены и координата, и эталон. Пустая ячейка в треке кадр пропускает.

`errors.csv` (разделитель `;`):

| Колонка | Смысл |
|---|---|
| `Frame` | номер кадра с нуля |
| `Err_X`, `Err_Y`, `Err_Z` | ошибка по оси, см; пусто, если нет оценки или эталона |
| `Dist_cm` | евклидова ошибка, см |

## Что появляется в `outputs/track_<время>/`

| Файл | Когда |
|---|---|
| `track.csv` | общий трек: `Frame;Loc_X;Loc_Y;Loc_Z`, сантиметры. Пустые ячейки — на кадре не было точки |
| `camN.csv` | монокулярная точка этой камеры: луч × плоскость Z. Не зависит от фильтра |
| `errors.csv` | покадровые ошибки против эталона |
| `coordinates_time.png` | три панели X, Y, Z от номера кадра. Оценка синяя, эталон зелёный |
| `trajectory_topdown.png` | путь в плоскости XY. Зелёная точка — старт, красная — конец |
| `camN.mp4` | ролик с боксом и строкой `X Y Z` |
| `space.png` | изометрия из окна, вкладка «Пространство» |

`csv` пишет таблицы и оба графика. `video` пишет только ролики. Галочки в окне можно сочетать отдельно: CSV, графики, видео.

## Окно

```bash
uv run python -m mv3d ui
```

Тёмное окно PyQt6, четыре вкладки справа.

**Список камер.** Имя, файл калибровки и фокус в миллиметрах. «Сохранить в конфиг» переписывает блок `cameras` в `configs/cameras.yml` и не трогает ширину, сенсор и `object_plane_z_cm`. «Исходные 5» возвращает cam1–cam5. «Таблица видео» строит строки под выбранное число камер: к каждой крепится ролик с любым именем (`mp4`, `avi`, `mkv`, `mov`). Плеер слева листает исходные кадры, без детектора.

**Что посчитать.** Галочки CSV / графики / видео, лимит кадров (`0` — все), путь к эталону. Пустой эталон отключает сравнение. «Запустить» пишет временный `outputs/_ui_cameras.yml` с выбранными роликами и гоняет тот же `run_tracking`. Лог идёт кадр за кадром. «Стоп» обрывает после текущего кадра и всё равно сохраняет папку.

**Камеры** — превью исходных роликов. **Графики** — `coordinates_time.png` и вид сверху. **3D координаты** — таблица кадра, X, Y, Z и `Dist_cm` из `errors.csv`; над таблицей последняя точка и строки MSE/RMSE из лога. **Пространство** — изометрия: белым общий путь, цветом следы камер. Слайдер и «Движение» проигрывают путь. Далекие монокулярные выбросы (дальше ~1.4 размаха общего трека) на сцену не попадают.

## Конфиг

`configs/cameras.yml`:

```yaml
image_width: 1280
image_height: 720
sensor_width_mm: 23.76
sensor_height_mm: 13.365
object_plane_z_cm: 300.0
cameras:
  cam1:
    video: configs/cam1.mp4
    calibration: configs/calibration/object_transform_CineCameraActor1.csv
    focal_mm: 35.0
```

Ролик без файла или без калибровки останавливает прогон с именем камеры. В комментарии конфига отмечено, какой ролик соответствует какой позе: в общий трек чужой вид входит, только если его луч согласован с уже найденной точкой.

Калибровка камеры — CSV на каждый кадр, тот же порядок кадров, что у ролика. Если в заголовке есть поле focal, оно перекрывает `focal_mm`.
